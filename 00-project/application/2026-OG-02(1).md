# Implementation of a Consistent Dynamic Game World in a Text Adventure Based on Large Language Models

## My interpretation of the brief

The project is a text-based adventure game in which a large language model generates a dynamic narrative in response to the player's decisions. The language model should not be responsible for remembering or deciding every fact. Important information about characters, locations, objects, events, and player progress must be stored in a separate structured world model and supplied to the model when needed.

The central challenge is maintaining logical consistency during long sessions. The application must update both the narrative and the structured world state, allow games to be saved and continued, and prevent or detect contradictions such as a character appearing in two locations or the player using an unavailable object.

## Proposed approach

I would begin by defining the game rules and a structured world model containing characters, locations, objects, relationships, quests, and important events. Deterministic program logic would validate movement, inventory changes, and other important state transitions, while the LLM would generate narration, dialogue, and proposed story developments within those constraints.

I would compare at least two memory approaches: sending a limited recent conversation with a structured state summary, and using summaries or retrieval to select relevant past events. The comparison would consider narrative consistency, token usage, response time, and scalability. A Python backend, a lightweight database such as SQLite, and a simple web interface would provide a practical first implementation. The LLM integration would be isolated behind an adapter so that an API-based or local model could be tested without changing the game logic.

## Initial plan

1. Define the game scope, player flow, deterministic rules, and structured world-state schema.
2. Research and compare context and memory-management approaches for longer sessions.
3. Prototype the LLM communication layer and validate structured inputs and outputs.
4. Implement state transitions, contradiction checks, save and continue functionality, and automated tests.
5. Build the user interface and integrate narrative generation with the validated world state.
6. Evaluate consistency, token usage, performance, and usability across several longer test sessions.

## Additional information

I would keep API keys and user data outside the repository and maintain the project with Git from the beginning. The MVP would focus on a small but coherent world and reliable state handling before optional features such as generated maps, advanced NPC memory, or multiplayer support.
